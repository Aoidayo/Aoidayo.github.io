ArrayList

Q：和LinkedList的区别
A：

增删改查，存储方式都不同

  • 存储方式：ArrayList分配一篇连续空间进行存储，LinkedList使用链表存储。LinkedList还有prev和next，存储大小比ArrayListNode更大。

  • 增删改查的时间复杂度：

    • 增：中间增加一个元素，ArrayList找是o(n)，插入是o(n), 除非是插入最后一个且cap没有满，需要重新创建分配数组；LinkedList找是o(n), 插入是o(1)。
    • 删除：同理
    • 改：ArrayList修改元素随机访问o(1)， linkedList到那个位置的时间开销o(n)
    • 查：随机访问位置o(1)，但是如果是查询指定元素都需要o(n)
Q：ArrayList的扩容原理？
A：

size达到cap，下次增加的时候需要grow(capacity)，开辟一块1.5*cap的新区域，存放原数组。

  • 何时触发扩容？增加元素的时候size=cap
  • 扩容倍数为什么是1.5？统计值，不一定需要是这个；总的来说过分低的话容易频繁扩容，过分高的话浪费内存。
Q：ArrayList的线程安全？
A：

ArrayList本身是线程不安全的，其中对exptectedModCount的伪cas操作并不保证线程安全。

  • ArrayList的所谓”线程安全“

    • ArrayList在调用函数进行修改的时候，有对modCount做操作。但是只是校验而已，无法保证线程安全。
    • expectedModCount = modCount
// 进行一系列操作，比如序列化等等
if(expectedModCount == modCount) throw ....
else return ...

  • 如何实现ArrayList的线程安全呢？

    • 读写加锁：例子是SynchronizedList，读写都加锁。

    • 写加锁：例子是CopyOnWriteList，写时加锁复制并修改，修改完成后修改原list指向然后释放锁。

      • 读的时候如果不并发写，就是读原copyOnWriteList。如果并发写，就是读旧的CopyOnWriteList。

    • 引申：ConcurrentHashMap是弱一致性迭代器，部分并发修改可以被iterator看到。

    • Concurrent的iterator：并发集合的迭代器都是在旧的容器上做迭代。Concurnnet集合是否用的也是CopyOnWrite呢？

HashMap

Q：桶数组内部在元素比较多的时候，存储结构为什么选择红黑树？
A：
同一个桶位置上，元素比较多的时候使用红黑树。是因为红黑树是 适合在内存中维护的自平衡二叉树，旋转维护二叉平衡的成本比AVL低，查找成本接近lgn。对比B+树，B+树适合在磁盘中维护，适合少磁盘io的，但是在内存中的效率较低，不如红黑树。
Q：HashMap的扩容机制。
A：

扩容，主要指的是桶数组的扩容与HashMap中Node的重分配。

HashMap的capacity指的是桶数组长度，size是key-valueNode数量。

当Node的size数量达到capacity的0.75倍时，扩展桶数组到2*capacity，同时重新分配每个Node的新binIndex。

HashMap的put流程：

  • 元素Node(key, value), 先取key.hashCode，过hash函数也就是高低位16位混合hashCode得到mixedKey。然后mixedKey&cap-1得到binIndex。

  • 如果binIndex 中没有元素直接插入，如果有则在对应的链表数组或者红黑树中对比。

    • 如果没有相同的元素，则插入。
    • 如果有相同的元素（hashCode是否相同，key是否==，key是否equals），替换value。

Q：HashMap什么时候桶数组上的元素链表转树？
A：

桶数组长度大于64，同时当前位置链表长度大于8时，需要转红黑树。说明此时哈希质量变差，频繁哈希冲突导致一个位置上有多个数，此时需要转红黑树提高查询效率。

什么时候转回去呢：当链表长度<6的时候，红黑树转链表。

为什么不在8转：避免来回转换，不必要开销。

Q：HashMap的loadFactor为什么设置为0.75？
A：
统计值，不一定要是这个。但是设置太高的话，容易频繁哈希冲突；如果设置太低的话，浪费内存。
Q：为什么重写equals后要重写hashCode？相同的equals应该拥有相同的hashCode？
A：
数据一致性，否则在hahsmap中就可以存储两个相同的key了。
Q：HashMap中存储的元素为什么是无序的？
A：
在扩容的时候，即时是尾插也会导致乱序，没办法有序。
